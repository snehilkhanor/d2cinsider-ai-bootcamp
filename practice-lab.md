# Practice lab (optional pre-work)

**Time:** 15 minutes, at home, after [Session 0](session-00-setup.md)
**You walk out with:** the five moves you will repeat all day, already familiar

Bootcamp day moves fast. Founders who have done these five things once spend the day thinking about their brand. Everyone else spends the first hour finding the buttons.

This lab uses the sample brand, Little Lab, so nothing here touches your own files. Everything it creates goes into `my-work/practice/`, which you can delete afterwards.

---

## Move 1. Ask about one file

Type this into the prompt box:

```
Read examples/little-lab/sample-inputs/reviews-export.csv and give me a five line summary of what customers are saying. Split it into what is working and what is not.
```

**Notice:** it did not hand rows back to you. It read all of them and told you what they mean.

## Move 2. Ask across several files

```
Some reviews say the Bath and Hair Wash "doesn't lather". Check the other files in examples/little-lab/sample-inputs/ as well. How often does this come up, and what is the customer actually worried about?
```

**Notice:** the answer draws on reviews, support tickets and email threads together. One finding, spread across three files, found in seconds. This is what the Customer Researcher does for your brand in Session 03.

## Move 3. Have it write a file

```
Write a one-page summary of Little Lab's top three customer complaints, with one real quote for each, and save it as my-work/practice/complaints.md
```

It may ask permission to create the file. Say yes.

**Now click the file path in the reply.** The file opens beside the chat. You will do this dozens of times on bootcamp day. Nothing is finished until you have opened it and read it.

## Move 4. Have it change a file

```
In my-work/practice/complaints.md, add a short line under each complaint suggesting what the brand could say on the product page to prevent it.
```

**Notice:** it changed the file you already had. You did not copy, paste or retype anything.

## Move 5. Push back

Pick the weakest suggestion it made and say why, in your own words. For example:

```
The second suggestion sounds like marketing. Rewrite it the way a founder would say it to a customer on WhatsApp.
```

**This is the move that matters most.** The first answer is a draft. Your judgement is what makes it good. Every session on bootcamp day ends with you reading the output and correcting it.

---

## Three habits to take with you

1. **Start a new chat for a new job.** A long chat gets slow and muddled. On bootcamp day you start a fresh one for each session.
2. **Say what you want it saved as.** If you name the file and folder, you can find it later.
3. **When it asks permission, read what it is asking.** Creating and editing files inside this folder is normal. If a request ever surprises you, say no and ask it to explain.

## Check it worked

- [ ] `my-work/practice/complaints.md` exists and you opened it by clicking its path
- [ ] You changed it once by asking
- [ ] You disagreed with something and got a better version

## Clean up

```
Delete the folder my-work/practice/
```
